# Sources for an open technology decision

Use this reference only when selecting or replacing a dependency or investigating an uncertain capability.

Start with the project's existing stack and constraints. Use official documentation, release notes, source repositories, supported-version policies, and licence text to verify the specific use case. Package registries help identify versions and dependencies. Discovery lists can suggest candidates, but are not evidence that a tool meets the requirements.

Compare plausible candidates on the capability needed, compatibility, maintenance and security support, operational burden, and migration cost. Verify relevant claims in primary sources and link those sources in the design. Popularity, issue counts, and last-commit dates are context, not scores that decide the outcome. A stable library may have little recent activity.

Research should end when there is enough evidence for the decision. State any unresolved consequential uncertainty. Do not require an ecosystem survey or a fixed number of alternatives for an established project choice.
